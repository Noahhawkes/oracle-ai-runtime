# Product: ORACLE.AI

**Last updated:** 2026-06-12
**Method:** codebase scan + session context

## Product Identity

- **One-liner:** Noah opens a terminal, types a thought or a task, and ORACLE remembers it, compresses it into meaning, routes it to the right tool or agent, and builds a governed record of his life and work that persists across every session.
- **Category:** personal-ai-operator / sovereign-continuity-system
- **Product type:** Single-user (B2C, single sovereign — Noah Hawkes / SOV1.AI)
- **Collaboration:** single-player — one sovereign, one system, one machine

- **Billing integration:** None detected. Stripe/Paddle not present.

## Tech Stack

- **Primary language:** Python 3.11+
- **Framework:** Custom event loop (`oracle.py` main loop, `resident_runtime.py` daemon)
- **Database:** SQLite (memory, facts, sessions, remember_me candidates, mindcoin ledger)
- **Background jobs:** Threading-based daemon (`resident_runtime.py` on N-minute interval, `meaning_engine.py` OBS watcher, wake_bg thread on startup)
- **LLM clients:** Anthropic SDK + OpenAI-compatible client for local Ollama models (`qwen2.5:7b` default local, Claude via API as fallback/primary)
- **Module organization:** Python packages in `core/`, docs in `docs/`, reference in `reference/`, messages/channels in `Messages/`

## Value Mapping

### Primary Value Action
**Memory approval** — Noah reviews a PENDING candidate meaning generated by ORACLE and approves it into durable memory. If this drops to zero, the system is recording but not remembering — continuity fails.

### Core Features (directly deliver value)
1. **Companion Mode** — Noah talks to ORACLE in natural language; ORACLE responds with full context of his life, projects, and state. The direct human connection layer.
2. **Memory Engine** — Raw experience → compressed meaning → PENDING candidate → Noah approves → durable SQLite record. The continuity infrastructure.
3. **OBS Meaning Capture** — Recording sessions automatically detected, transcribed (Whisper, planned), and submitted as memory candidates. Renders lived sessions into permanent record.
4. **Approval Center** — All irreversible actions and memory candidates surface here for the 51% sovereign gate. Governance layer.
5. **MindCoin Ledger** — Milestone tracking and reward system that marks breakthrough moments as durable Mythic LootDrops.

### Supporting Features (enable core actions)
1. **Wake Memory** — On every boot, injects Noah's identity, active projects, and continuity anchors into the system prompt so ORACLE always knows who he is.
2. **SOV1 Hands (computer_control)** — Keyboard/mouse automation that executes approved actions on the physical machine.
3. **Claude Code Bridge** — Channels work between ORACLE (companion/operator layer) and Claude Code (implementation layer).
4. **Project State** — Tracks active project, current phase, blockers, and next recommended step across sessions.
5. **Resident Dashboard** — HTML presence window showing live status, pending approvals, and active project.
6. **Salience + Attention Filter** — Scores inputs by meaning weight before routing, preventing noise from reaching the memory layer.

## Codebase Observations

- **Feature areas inferred:** Companion conversation, memory compression, OBS session ingest, computer control/actuation, project state management, multi-agent routing (Claude Code, Codex, ChatGPT bridges), resident daemon, dashboard/presence UI, MindCoin reward ledger, self-build/improvement loop
- **Entity model inferred:** Single sovereign user → projects → memory candidates → durable facts. No accounts, no teams, no multi-tenancy — intentionally.
- **Architecture pattern:** Event loop with salience-gated routing. All inputs pass through `cognitive_salience.py` → `attention_filter.py` → router → tool or LLM → approval gate → memory.
- **Governance model:** 51/49 rule enforced in code — ORACLE renders 49%, Noah approves 51%. No autonomous writes to durable memory without human gate.
