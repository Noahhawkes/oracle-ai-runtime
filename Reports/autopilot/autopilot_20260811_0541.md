## What I did this session: (d) general hardening — test coverage gap

Went looking for load-bearing modules with zero pytest coverage. Found `core/epistemic_ledger.py` (1,118 lines, committed back in June, **not new** — stable code): the deterministic claim-approval ledger that `cognitive_spine.py`, `cognitive_state.py`, and `doubt_detection.py` all import. It enforces real policy (models can propose claims but never verify them; VERIFIED requires a bound approval token, independent non-model evidence, and an authorized approver; failed approvals must leave the ledger byte-for-byte unchanged; contradictions must be disposed of before a claim can clear). It already had a thorough 22-check `_smoke_test()` — but that only runs via `python core/epistemic_ledger.py --smoke-test`, which nothing in the repo calls, so it never executes in the normal health pass and a regression here would go undetected by `pytest tests/`.

Added `tests/test_epistemic_ledger.py` — 21 pytest cases (one smoke-test check, "Companion Mode cannot mutate," was split across two tests to also cover `dispute_claim`/`retract_claim`, which the original smoke test didn't touch) covering:

- model-proposed claims can never auto-become VERIFIED
- unsupported INFERENCE/UNKNOWN claims stay unsupported
- contradiction linking is bidirectional and rejects self-reference
- supersession preserves the old claim in revision history
- Companion Mode is blocked from every mutation path (propose/dispute/retract)
- `approve_claim` rejects: non-APPLICATION callers, expired tokens, tokens bound to the wrong claim, stale `expected_revision`, missing evidence, model-output-only evidence, unresolved blocking contradictions
- a failed approval leaves the ledger hash-identical (no partial writes)
- a valid SUPPORTED→VERIFIED transition creates a receipt, bumps revision, keeps the prior revision retrievable, and rejects token reuse
- `search_claims` filters by text and status; `get_open_questions` includes a priority score; `get_claim`/`dispute_claim`/`retract_claim` handle missing IDs correctly

Each test uses its own `tmp_path` ledger — no shared state, no live-server interaction, no writes outside pytest's tmp directory.
