# Workshop Plan

Course title:

```text
VibeCode Masterclass: Build With AI Without Losing the Wheel
```

Tagline:

```text
Receipts Over Vibes
```

## Audience

- Beginners using AI for work or school.
- Founders and creators building products.
- Operators managing multiple AI tools.
- Educators and students learning AI literacy.
- Small business owners using AI for documents, code, content, and automation.

## Learning Outcomes

By the end, students can:

1. Separate prompting from steering.
2. Write a five-part VibeCode command.
3. Convert a feeling of drift into a target, boundary, test, and receipt.
4. Use queue reset language when prompt piles become unsafe.
5. Identify fake execution claims.
6. Separate candidate from canon.
7. Assign AI systems to distinct roles.
8. Run a simple acceptance test and demand evidence.
9. Preserve human authority in AI-assisted work.

4. Close: human warning, anti-mind-ripper protocol, next-practice plan.

## Signature Exercise

Exercise name:

```text
From Vibe to Receipt
```

Student writes:

```text
This feels wrong because...
```

Then converts it into:

- Intent
- Boundary
- Target
- Test
- Receipt

Example:

```text
Feeling:
The app feels like it forgot who it is.

VibeCode translation:
The response is using a generic opener instead of the product identity. Patch
the response synthesis layer to suppress generic openers for protected domains.
Do not hardcode exact prose. Run the synthesis tests and live UI probe. Report
changed files and sample output.
```

## Final Build Challenge

Students receive a messy AI build thread. They pass if they:

- Stop the prompt pileup.
- Recover current state.
- Identify the active task.
- Issue one clean command.
- Require tests.
- Require receipts.
- Avoid scope creep.
- Preserve human authority.
