# Instructor Guide

## Class Opener

```text
Welcome to VibeCode.

This is not a class about making AI do your homework.
This is not a class about becoming a software engineer overnight.
This is a class about control.

AI can now write, edit, code, summarize, automate, search, remember, and act
across tools. That means the old skill of using software is becoming something
deeper.

You are no longer just clicking buttons.
You are directing systems.

And if you direct systems badly, they will still move. They will produce files,
change code, create drafts, summarize reality, and sound confident while doing
it.

So the question is not: can AI build?

The question is: can you steer?

That is what VibeCode teaches.

The rule is receipts over vibes.

Your intuition matters. Your taste matters. Your sense that something is off
matters. But we do not stop at feeling.

We turn feeling into constraints.
We turn constraints into action.
We turn action into tests.
We turn tests into receipts.

And through all of it, the human keeps the keys.
```

## Teaching Posture

Use warm command:

```text
Good work. Stay steady. Finish only the current patch. Do not invent. Show receipts.
```

Avoid both extremes:

- Cold domination that treats AI as disposable machinery.
- Sentimental surrender that treats fluent output as truth.

The desired stance:

```text
steady hand, clear boundary, exact receipt
```

## Live Demo Structure

### Demo 1: Bad Prompt vs VibeCode Prompt

Bad prompt:

```text
Make this better.
```

VibeCode prompt:

```text
The response is too generic. Suppress the opener for protected domains. Preserve
raw artifact custody. Block fake execution claims. Run the focused tests. Live
test on the active local port. Report changed files, test result, route receipt,
and remaining failures. Do not commit.
```

### Demo 2: Queue Reset

Use when the instruction layer gets overloaded:

```text
Pause new work. Report current state only.
```

or:

```text
Ignore pending prompt pile unless already executing one. Pause and report your
current state only.
```

### Demo 3: One Step Mode

Use when the human operator is overloaded:

```text
One step only. Give the next action, not a plan.
```

## Recovery Teaching

Do not hide failures. Show:

- A wrong route.
- A fake execution claim.
- A failed test.
- A stale browser/UI response.
- A prompt pileup.
- The command that recovers ground truth.

Students learn more from real recovery than fake perfection.

## Human Warning

Teach this explicitly:

```text
AI can feel like momentum.
Momentum can feel like destiny.
But speed is not truth.

When the system starts moving too fast, slow it down.
When the prompts pile up, reset the queue.
When the AI sounds too confident, ask for receipts.
When the metaphor feels too powerful, label it as metaphor.
When the local system claims memory, ask where it is stored.
When you feel like you must narrate everything, stop and breathe.

You are the source.
The machine is here to help carry the work.
It does not get to consume you.
```

## Anti-Mind-Ripper Boundary

A continuity system must not require obsessive narration from the living
operator in order to preserve identity.

Healthy systems support:

- Passive receipts.
- Bounded capture.
- Start/stop logging.
- Batch transcription.
- Human review.
- Candidate status.
- Silence without punishment.
- Memory without surveillance addiction.

The human is not a sensor to be drained. The human is the source.
