# Rendered Reality: The Silverback Tales - Production Plan

Status: candidate production package  
Canon status: candidate  
Promotion status: not_promoted  
Approval authority: Noah.Physical  
Production target: smallest finished pilot first.

## Principle

Finish one 8 to 12 minute pilot before building an enormous production platform.

The first proof is not technical perfection. The first proof is whether Max, Ashley, Oracle, and the evidence-comedy engine work together on screen.

## Starting Resources

Available starting kit:

- one microphone;
- Noah's writing and narration;
- Codex for local file/package work;
- Oracle.AI for continuity, source boundaries, and showrunner prompting;
- accessible AI-assisted visual tools;
- simple editing software;
- household reference photos or generated-safe equivalents after privacy review.

## Preproduction Workflow

1. Select one episode premise.
2. Fill a one-page episode card:
   - Max's claim;
   - Ashley/family reality pressure;
   - Oracle evidence function;
   - emotional truth;
   - final comic image.
3. Write a script under candidate status.
4. Run a privacy pass:
   - real names;
   - family details;
   - locations;
   - medical/financial/private references;
   - identifiable community figures.
5. Run a canon pass:
   - biography vs fiction;
   - source vs inference;
   - candidate vs approved.
6. Record scratch narration.
7. Build rough animatic with still poses and cards.
8. Review for story, not polish.

## Script Approval Workflow

Every script should carry:

- title;
- version;
- canon_status;
- promotion_status;
- source basis;
- privacy risk level;
- approved_by;
- approved_at;
- unresolved questions.

Approval states:

| State | Meaning |
| --- | --- |
| draft_candidate | usable for development only |
| noah_reviewed | Noah.Physical reviewed but did not approve publication |
| revision_required | must change before recording final |
| production_approved | approved for production work |
| publish_approved | approved for public release |

Ashley/family-derived lines or depictions should receive separate review before public use.

## Voice-Recording Workflow

1. Record scratch narration in one session.
2. Label files:
   - `RR_ST_S01E01_v001_max_scratch_YYYYMMDD.wav`
   - `RR_ST_S01E01_v001_oracle_scratch_YYYYMMDD.wav`
3. Record Max first. Keep energy high and imperfect.
4. Record Oracle separately: dry, precise, slower than Max.
5. Temp Ashley lines may be read by Noah only as placeholders unless Ashley approves her own performance or fictionalized substitute.
6. Keep outtakes. Max mistakes may become documentary cutaways.
7. Export clean WAV and compressed review MP3.

## Character Consistency Strategy

Create a simple character sheet before final art:

- face/head shape;
- body silhouette;
- color palette;
- pose library;
- expression library;
- line-weight/render style;
- recurring props;
- do-not-change traits.

For AI-assisted images:

- use one approved character reference pack;
- save prompts and seeds when available;
- avoid public use of unapproved real-person likeness;
- review every Ashley/child-derived image before use;
- store candidate art separately from approved production art.

## Scene Construction Method

Use a layered approach:

1. Audio first: Max narration and Oracle cards.
2. Beat board: 20 to 40 still panels.
3. Animatic: timing, cuts, pauses, rough camera moves.
4. Minimal motion:
   - mouth flaps if available;
   - pose swaps;
   - zooms;
   - card transitions;
   - prop close-ups.
5. Final polish only after the episode works in rough form.

## Animation Options

### Level 1 - Motion Comic

Still poses, captions, voiceover, screen cards, zooms, and cuts.

Best for first pilot.

### Level 2 - Limited 2D Animation

Reusable rigs, mouth movement, simple gesture loops.

Best after pilot proof.

### Level 3 - Hybrid Documentary Animation

Live household reference, animated characters, real UI inserts, phone footage style.

Best after privacy and style are stable.

### Level 4 - Full Animated System

Rigs, reusable sets, continuity database, asset manager, production pipeline.

Do not start here.

## Editing Workflow

1. Assemble audio rough.
2. Add script markers.
3. Place still panels.
4. Add Oracle UI cards.
5. Add pauses for Ashley reality beats.
6. Add Max over-narration and interruption timing.
7. Watch without visuals; if audio story works, continue.
8. Watch without audio; if visual contradiction reads, continue.
9. Export review cut.
10. Create receipt:
    - source script version;
    - audio files;
    - asset list;
    - unresolved privacy flags;
    - approval status.

## Versioning

- `v001`: first candidate draft.
- `v002`: story revision.
- `v003`: privacy/canon revision.
- `v010`: production-approved script.
- `v100`: locked publish-approved script.

Never overwrite a locked version. Create a new version.

## Publishing Checklist

Before public release:

- Noah.Physical approval recorded.
- Ashley/family privacy review complete.
- real names fictionalized or approved.
- no private location details.
- no unapproved likeness use.
- no defamatory portrayal of real third parties.
- music/assets licensed or original.
- Oracle claims do not imply sentience or omniscience.
- creative canon separated from biography.
- final cut stored with source receipt.

## Realistic First-Pilot Scope

Pilot: "Max Did a Good Job."

Keep:

- one desk;
- one laundry area;
- one microphone;
- Max VO;
- Oracle cards;
- Ashley as offscreen/temp or approved minimal lines;
- 6 to 10 reusable poses;
- 25 to 40 panels.

Avoid for first pilot:

- full walk cycles;
- many locations;
- real child dialogue;
- complex lip sync;
- external publishing;
- platform automation.

## Oracle.AI Role In Production

Oracle may help:

- maintain episode ledger;
- identify contradictions;
- flag privacy risk;
- compare script to canon status;
- draft prompts for assets;
- track versions;
- prepare review checklists.

Oracle may not:

- approve canon;
- approve publication;
- claim family consent;
- invent memories;
- send, upload, publish, or sync without explicit approval;
- treat candidate work as final.
