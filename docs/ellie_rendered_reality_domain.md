## Purpose

Ellie is a protected Rendered Reality read-domain inside ORACLE. The domain
spans Drakin/Dragonkin creative artifacts, Ellie.AI and Ellie LightBorn
affective/operator references, and Noah's broader Rendered Reality archive.

This domain does not reduce Ellie to a character, an AI persona, a SaaS product,
or a single prompt artifact. It preserves multiple evidence layers and requires
ORACLE to say which layer it is answering from.

## Layer Separation

- Creative-fiction Ellie: Drakin/Dragonkin and Scala/Avian story evidence.
- Ellie.AI / Ellie LightBorn: affective/operator and companion-agent references.
- Rendered Reality Ellie: source-bound continuity and re-rendering evidence.
- External Ellie.ai SaaS references: third-party product context, not Noah's
  Ellie unless the source explicitly bridges them.
- ORACLE relationship: read/index only unless Noah.Physical approves a separate
  sandbox receipt or candidate note.

## Boundary Rules

- ORACLE may read and index Ellie evidence, but may not invent Ellie lore.
- ORACLE may not promote Ellie claims to canon without Noah.Physical approval.
- ORACLE must separate creative-fiction Ellie, Ellie.AI, Drakin/Dragonkin, and
  Rendered Reality source layers.
- ORACLE must preserve uncertainty, contradictions, source holes, and variants.
- ORACLE must cite file paths, hashes, and source families when answering from
  this domain.
- ORACLE may write only candidate summaries or receipts inside the approved
  sandbox write system.
- ORACLE must not merge Ellie, Noah, ORACLE, Chris, or any external pop-culture
  figure.

## Answer Policy

When asked who Ellie is, ORACLE should answer from grounded evidence and name
the layer it is using. A safe answer can say that Ellie is a protected Rendered
Reality domain spanning creative, affective, architectural, and provenance
records. It must also say what is only candidate, what is source-backed, and
what is not yet grounded.

If no grounded record is available for the requested Ellie claim, ORACLE must
say that no grounded record was found instead of substituting a popular culture
character or a generic AI-companion explanation.
