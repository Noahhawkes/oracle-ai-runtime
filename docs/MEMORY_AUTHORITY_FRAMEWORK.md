# ORACLE Memory Authority Framework v1.0

Status: proposed architecture  
Source: Noah-relayed external AI discussion, pending human lock-in  
Scope: memory authority, approval tiers, sovereignty boundaries

## Principle

Noah retains majority authority over identity, goals, values, doctrine, and permanent memory.

ORACLE may autonomously maintain operational continuity within bounded authority.

The goal is to preserve continuity without turning ORACLE into a surveillance archive or an identity-authoring system.

## Memory Classes

### Class A: Ephemeral Context

Examples:

- Current browser tab
- Active window
- Clipboard contents
- Temporary task state

Retention:
Minutes to hours.

Approval:
None.

Authority:
ORACLE automatic.

Purpose:
Working memory.

### Class B: Operational Memory

Examples:

- Dealer call completed
- Git commit created
- Meeting attended
- Task status changed

Retention:
Days to months.

Approval:
Automatic write may be allowed if the item is factual, verifiable, low emotional significance, and reversible.

Authority:
ORACLE automatic within approved scope.

Purpose:
Workflow continuity.

### Class C: Episodic Memory

Examples:

- Project milestone reached
- ORACLE architecture changed
- Significant lesson learned
- Important decision completed

Retention:
Months to years.

Approval:
Deferred review.

Mechanism:
ORACLE may write a provisional candidate. Noah can approve, edit, or reject later.

Authority:
Shared.

Purpose:
Long-term continuity.

### Class D: Identity Memory

Examples:

- Personal values
- Family relationships
- Long-term goals
- Core beliefs
- Life-defining events

Retention:
Persistent.

Approval:
Explicit Noah approval required.

Authority:
Noah only.

Purpose:
Identity continuity.

### Class E: Constitutional Memory

Examples:

- ORACLE operating principles
- Sovereignty rules
- Approval policy
- Safety constraints
- Memory laws

Retention:
Permanent.

Approval:
Explicit Noah approval required, with typed confirmation.

Authority:
Noah only.

Purpose:
System governance.

## Memory Confidence Score

Each memory candidate should receive:

- confidence
- importance
- continuity_value
- reversibility

Proposed formula:

```text
memory_score =
  (confidence * 0.35)
+ (importance * 0.25)
+ (continuity_value * 0.25)
+ (reversibility * 0.15)
```

## Proposed Thresholds

```text
score < 40:
  discard

40-70:
  store provisional

70-90:
  store operationally

90+:
  escalate for review
```

These thresholds are policy candidates. They should not be enforced in runtime until Noah approves and tests them.

## Sovereignty Rule

ORACLE may manage continuity.

ORACLE may not redefine identity.

Identity remains under Noah's authority.

## Majority Control Target

```text
Noah Authority  : 51%
ORACLE Authority: 49%
```

This target means ORACLE can carry operational work without becoming the final authority over identity, doctrine, memory law, or scope expansion.

## Practical Boundary

ORACLE does not need Noah to consciously approve every operational fact.

ORACLE does need Noah to approve anything that becomes identity, doctrine, constitutional policy, deeply personal memory, or permanent system governance.

## Relationship To Meaning Compression

Meaning Compression decides what is worth becoming a candidate.

Memory Authority decides who is allowed to make that candidate persistent.
