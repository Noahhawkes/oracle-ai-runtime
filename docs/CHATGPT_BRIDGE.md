# ORACLE ChatGPT Bridge
## ORACLE.AI — External AI Collaboration Doctrine

---

## Core Law

> **ORACLE may draft to ChatGPT.**
> **ORACLE may not submit to ChatGPT without Noah approval.**

---

## Purpose

Noah runs two screens. ORACLE runs in PowerShell/local mode on one screen. ChatGPT desktop app (or browser tab) is open on the second screen. The ChatGPT Bridge allows ORACLE to prepare structured, governed messages and transfer them to ChatGPT — without blind mouse coordinates, without automatic submission, and without leaking secrets.

---

## What This Is Not

- This is not an autonomous external API integration
- ORACLE does not call ChatGPT's API directly
- ORACLE does not submit messages automatically
- ORACLE does not share raw memory dumps, API keys, or private documents

---

## Bridge Message Envelope

Every message sent through the bridge is wrapped in a governed envelope:

```
ORACLE → ChatGPT BRIDGE MESSAGE
────────────────────────────────────────
Context:
[compressed, redacted context]

Request:
[specific question or task]

Constraints:
[governing constraints for the response]

Expected output:
[format and scope]

────────────────────────────────────────
Approval status : DRAFT
Message ID      : a1b2c3d4
Generated by    : ORACLE.AI (governed draft)
```

---

## Security: Secret Redaction

Before any message is drafted, the following patterns are automatically redacted:

- API keys (`sk-...`, `api_key=...`)
- Passwords (`password: ...`, `passwd=...`)
- SSNs (`XXX-XX-XXXX`)
- Credit card numbers
- Bearer tokens
- Raw secrets

Redaction count is recorded in every message. If redactions exceed expectations, the message is flagged for review.

---

## Window Detection

The bridge uses semantic window detection — never blind pixel coordinates:

1. **pywinauto UIAutomation** — preferred, finds window by title/class in accessibility tree
2. **pygetwindow title scan** — fallback, scans visible window titles
3. **Mouse click** — only with explicit `mouse_fallback=True` and verified target

Detection order: ChatGPT desktop app → Chrome tab → Edge tab → Firefox tab

If ChatGPT window is not found, the bridge stops and reports clearly. It does not open new browser windows.

---

## Workflow

```
1. draft_message()      — build envelope, redact secrets, compress context
2. find_chatgpt_window() — locate ChatGPT semantically (no coordinates)
3. insert_message()      — paste into input field (draft only by default)
4. [Noah reviews]
5. approve_send()        — Noah calls APPROVE_SEND_CHATGPT <id>; Enter is pressed
```

## Commands

### REPL Commands
```
/bridge-chatgpt-draft <question>    Draft a message to ChatGPT (dry run)
/bridge-chatgpt-status              Show bridge status and pending drafts
```

### Approval Command
```
APPROVE_SEND_CHATGPT <message_id>   Send a drafted message (Noah must type this)
```

### CLI
```bash
python core/chatgpt_bridge.py --status
python core/chatgpt_bridge.py --dry-run --message "What is X?"
python core/chatgpt_bridge.py --smoke
```

---

## Forbidden

- No automatic submission without Noah typing `APPROVE_SEND_CHATGPT`
- No sending API keys, passwords, SSNs, raw memory dumps
- No opening new browser windows to "find" ChatGPT
- No blind coordinate targeting
- No external API calls to OpenAI directly (this is window-level, not API-level)

---

## BridgeMessage Fields

| Field | Description |
|---|---|
| `id` | Unique message ID (used for approve_send) |
| `context` | Compressed, redacted context block |
| `request` | The specific question or request |
| `constraints` | Governing constraints for the response |
| `expected_output` | Format and scope of desired output |
| `approval_status` | DRAFT → APPROVED → SENT (or BLOCKED) |
| `target_window` | Which ChatGPT window was targeted |
| `dry_run` | True = described only, False = actually executed |
| `redactions_applied` | Number of secrets redacted |

## Integration Points

- `oracle_runtime.py` — can invoke bridge as part of a cycle
- `oracle.py` REPL — `/bridge-chatgpt-draft` command
- Future `action_queue.py` — bridge calls as governed action candidates

---

## Multi-Monitor Support

The bridge searches all visible windows across all monitors. No monitor index or coordinate assumption is made. If the ChatGPT window exists anywhere on the desktop (any monitor), it will be found.
